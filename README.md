# سامانهٔ ناوگان سپید

این مخزن دو برنامهٔ جدا دارد: رابط عملیاتی React در `frontend` و API مبتنی بر NestJS در `backend`. داده‌های عملیاتی مشترک در PostgreSQL نگه‌داری می‌شوند. فایل تک‌صفحه‌ای قبلی داخل `frontend/legacy` حفظ شده و در مسیر «محیط سازگار با نسخهٔ قبلی» کار می‌کند.

## اجرای توسعه در ویندوز

۱. Node.js نسخهٔ 24.7 یا بالاتر از شاخهٔ 24 را نصب کنید. اگر خوشهٔ محلی PostgreSQL پروژه ندارید، Docker Desktop را هم اجرا کنید.
۲. از ریشهٔ پروژه `dev.bat` را اجرا کنید. اگر وابستگی‌ها نصب نباشند، اسکریپت آن‌ها را نصب می‌کند، PostgreSQL توسعه را بالا می‌آورد و پنجرهٔ فرانت و بک‌اند را باز می‌کند. اگر پوشهٔ دادهٔ محلی `.dev-postgres` وجود داشته باشد، از همان استفاده می‌کند و برای شروع توسعه به Docker نیاز نیست.
۳. برنامه در `http://127.0.0.1:55321` و سلامت API در `http://127.0.0.1:55320/api/v1/health/ready` در دسترس است.
۴. برای ساخت مدیر اولیه، `setup-admin.ps1` را اجرا کنید. رمز فقط برای همان اجرای ساخت حساب دریافت می‌شود و در پایگاه‌داده به شکل hash ذخیره خواهد شد.

برای استفاده از PostgreSQL خارجی، فایل `backend/.env` را با اتصال همان سرور آماده کنید و `dev.bat --external-db` را اجرا کنید. مقدارهای `.env` را در مخزن یا فرانت قرار ندهید.

## دادهٔ آغازین

فهرست ۱۱ ماشین، ۷ مدل و ۹ پرسنل از دادهٔ آغازین نسخهٔ اصلی آمده است. migration یازدهم آن را فقط وقتی اضافه می‌کند که جدول‌های ناوگان و فضای سازگاری خالی باشند. تعمیرات، تحلیل‌ها، قطعات و سابقهٔ نگهداری اولیه خالی می‌مانند؛ برای همین هشدارهای نگهداری تا زمان تعریف قطعات و ثبت کارکرد نمایش داده نمی‌شوند.

اطلاعاتی که فقط در IndexedDB مرورگر قدیمی‌اند به‌طور خودکار به سرور منتقل نمی‌شوند. از همان مرورگر قدیمی JSON بگیرید، آن را در محیط سازگار روی سرور بارگذاری کنید، سپس در رابط React از صفحهٔ «انتقال دادهٔ نسخهٔ قبلی» پیش‌نمایش را بررسی و انتقال به جدول‌های عملیاتی را اجرا کنید. فایل واقعی و تطبیق شمار رکوردها باید در محیط شرکت انجام شود. وضعیت تفصیلی در [جدول تطبیق قابلیت‌ها](sepid-fleet-system/feature-parity.fa.md) ثبت شده است.

## پیامک و پشتیبان

مدیر کل می‌تواند در «تنظیمات و گزارش پیامک» درگاه IPPanel یا SMS.ir را انتخاب و کلید و فرستندهٔ آن را ذخیره کند. برای فرم تنظیمات، یک مقدار ۳۲ بایتی با نمایش هگز در `SMS_CONFIG_ENCRYPTION_KEY` روی سرور تنظیم کنید و همان مقدار را به API و worker بدهید. این کلید را جدا از پشتیبان دیتابیس نگه دارید تا پس از بازیابی بتوان تنظیمات را خواند. برای جزئیات دریافت Patternها، تنظیم کد ورود و پیکربندی امن، [راهنمای IPPanel](docs/ippanel-setup.fa.md) را ببینید. ذخیرهٔ تنظیمات بدون فعال‌سازی، ارسال را در حالت شبیه‌سازی نگه می‌دارد.

ارسال توسعه‌ای به‌صورت پیش‌فرض شبیه‌سازی می‌شود. برای پیکربندی محیطی IPPanel، `SMS_PROVIDER=ippanel` به‌همراه `IPPANEL_API_KEY` و `IPPANEL_SENDER` را فقط در محیط سرور قرار دهید؛ در Compose این مقادیر باید به API و worker داده شوند. SMS.ir و کاوه‌نگار همچنان مسیرهای قدیمی خود را دارند. گزارش پیام شامل شناسهٔ سرویس و استعلام وضعیت است. دریافت اعلان خودکار خاموش است تا مدیر آن را فعال کند و کاربر هم رضایت و شمارهٔ معتبر داشته باشد.

پشتیبان PostgreSQL با سرویس جداگانهٔ Compose زمان‌بندی می‌شود و نسخه‌ها را در volume محدود نگه می‌دارد؛ این volume جای نسخهٔ خارج از میزبان را نمی‌گیرد. پیش از استقرار واقعی، فایل محیطی امن، دامنه/HTTPS، کپی خارج از سرور و تمرین بازیابی روی پایگاه جدا برای محیط مقصد آماده شوند.

## ساخت و بررسی

از پوشهٔ `frontend` و `backend` دستور `npm run build` را جدا اجرا کنید. سناریوی کامل مرورگر را می‌توان از `backend` با `npm run test:browser` اجرا کرد؛ روی Windows Chrome در مسیر پیش‌فرض به‌صورت خودکار انتخاب می‌شود و در صورت نصب در مسیر دیگر، `CHROME_BIN` را تنظیم کنید. سناریو داده‌ها را در یک schema موقت جدا ثبت و پس از اتمام حذف می‌کند.
