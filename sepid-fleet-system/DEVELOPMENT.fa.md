# راهنمای توسعهٔ نسخهٔ آنلاین

## اجرای محلی

پروژهٔ فعال از دو برنامهٔ جدا تشکیل شده است: React/Vite در پوشهٔ `../frontend` و NestJS در `../backend`. PostgreSQL توسعه با Compose بک‌اند اجرا می‌شود. برای شروع در Windows، Docker Desktop را باز و `../dev.bat` را اجرا کنید؛ این فایل سرویس دیتابیس و پنجره‌های فرانت و بک‌اند را بالا می‌آورد.

- فرانت: `http://127.0.0.1:55321`
- آمادگی API: `http://127.0.0.1:55320/api/v1/health/ready`
- ساخت فرانت و بک‌اند: از پوشهٔ هرکدام `npm run build`
- آزمون API: از `../backend` دستور `npm run test:api`
- آزمون مرورگر: از `../backend` دستور `npm run test:browser`؛ متغیر `CHROME_BIN` باید به Chrome یا Edge نصب‌شده اشاره کند.

آزمون‌های API و مرورگر schema تصادفی موقت می‌سازند و در پاک‌سازی پایانی حذف می‌کنند؛ آن‌ها نباید جدول‌های محیط توسعه یا production را تغییر دهند.

## ساختار و داده‌ها

- `../frontend/` رابط عملیاتی React و صفحهٔ سازگاری با رابط قبلی را دارد.
- `../backend/` API، migrationها و آزمون‌های ایزوله را دارد.
- `./` شامل سورس اصلی، سند اجرایی و جدول وضعیت تطبیق است.
- دادهٔ آغازین ماشین‌ها از migration نسخه‌بندی‌شده فقط به دیتابیس کاملاً خالی افزوده می‌شود.
- دادهٔ IndexedDB مرورگر قبلی خودکار وارد PostgreSQL نمی‌شود. مدیر می‌تواند فایل JSON را در نسخهٔ سازگار بارگذاری کند؛ پیش‌نمایش و ورود تراکنشی به جداول عملیاتی React پیاده شده‌اند. فایل پشتیبان واقعی کاربر هنوز باید پیش از مهاجرت نهایی بررسی و شمار رکوردها و روابط آن تطبیق داده شود.

## وضعیت تحویل

وضعیت هر حوزه و آزمون‌های انجام‌شده در [جدول تطبیق قابلیت‌ها](feature-parity.fa.md) نگه‌داری می‌شود. رودمپ جاری برای تطبیق دیداری صفحه‌به‌صفحه، رفتار داده و پذیرش استقرار در [ممیزی و رودمپ تطبیق](ROADMAP-PARITY.fa.md) است. سند [طرح اجرایی](IMPLEMENTATION-PLAN.fa.md) مبنای دامنه و معیارهاست؛ صفحهٔ `backend/README.md` و فایل‌های ریشهٔ پروژه راهنمای اجرای فعلی‌اند.

محیط توسعه آماده است، اما این به‌معنی پایان پذیرش یا استقرار عملیاتی نیست. انتقال دادهٔ واقعی، تکمیل قابلیت‌های باقی‌ماندهٔ نسخهٔ مرجع، دامنه و HTTPS، پشتیبان خارج از میزبان و تمرین بازیابی باید پیش از استفادهٔ production انجام شوند.
