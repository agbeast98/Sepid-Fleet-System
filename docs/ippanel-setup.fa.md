# راهنمای اتصال IPPanel

سامانه از API رسمی IPPanel Edge استفاده می‌کند. درگاه IPPanel کنار اتصال قدیمی SMS.ir نگه داشته شده و انتخاب و فعال‌سازی هر درگاه از صفحهٔ «تنظیمات و گزارش پیامک» انجام می‌شود.

## آماده‌سازی پنل

1. در پنل IPPanel از بخش **Developers → Access Keys** یک API key بسازید. کلید را فقط در تنظیمات مدیر سامانه یا متغیر محیطی سرور وارد کنید.
2. شمارهٔ فرستنده‌ای را بردارید که برای حساب IPPanel فعال و مجاز است. این سامانه شماره را با قالب E.164 می‌گیرد؛ نمونه: `+983000505`.
3. در صفحهٔ Pattern پنل، قالب‌های موردنیاز را بسازید و تا فعال‌شدن/تأییدشدن آن‌ها صبر کنید. نام متغیرهای قالب باید دقیقاً با کلیدهای ارسالی API یکسان باشد.

## پیکربندی امن

- در `.env` بک‌اند و سرویس worker مقدار `SMS_CONFIG_ENCRYPTION_KEY` را به کلید hex سی‌ودوبایتی اختصاص دهید. همان کلید باید در هر دو سرویس یکسان باشد و جدا از dump پایگاه داده نگه‌داری شود.
- برای پیکربندی از رابط، به‌عنوان مدیر کل وارد «تنظیمات و گزارش پیامک» شوید، درگاه **IPPanel** را انتخاب کنید، API key و شمارهٔ فرستنده را وارد کنید و تنظیمات را ذخیره کنید. کلید در PostgreSQL با AES-256-GCM رمز می‌شود؛ API آن را به مرورگر برنمی‌گرداند. برای حفظ کلید قبلی، فیلد کلید را خالی بگذارید.
- به‌جای رابط، در صورت نیاز به پیکربندی محیطی، `SMS_PROVIDER=ippanel`، `IPPANEL_API_KEY` و `IPPANEL_SENDER` را در محیط API و worker تنظیم کنید. مقادیر محرمانه را در Git، image یا لاگ قرار ندهید.
- برای دریافت کد OTP ورود، کد قالب فعال را ثبت کنید و نام متغیرهای نام کاربر و کد را مطابق قالب همان پنل تنظیم کنید. تا پیش از ثبت کد قالب، ورود با OTP آماده نمی‌شود.
- ارسال واقعی تنها با انتخاب درگاه و روشن‌کردن گزینهٔ فعال‌سازی ممکن است. پس از فعال‌سازی هم ارسال آزمایشی از سامانه درخواست تأیید می‌کند.

## قالب‌های پیامک تعمیرات

در جدول قوانین هر مرحله، کد قالب IPPanel را وارد کنید. دکمهٔ دریافت قالب‌ها، قالب‌های فعال را مستقیماً از API پنل می‌خواند و کد قابل انتخاب می‌شود. در نگاشت پارامترها هر خط به‌شکل `نام_متغیر=متغیر_سامانه` است؛ برای نمونه:

```text
MACHINE=ماشین
STAGE=مرحله
CODE=توضیح
```

کلید سمت چپ باید با نام متغیر Pattern در پنل یکی باشد. مقدار سمت راست از اطلاعات پرونده پر می‌شود. برای Pattern IPPanel، شمارهٔ فرستنده نیز باید برای حساب تنظیم شده باشد.

## APIهای مورد استفاده

Base URL رسمی `https://edge.ippanel.com/v1` است و کلید در header با نام `Authorization` فرستاده می‌شود.

- ارسال متن: `POST /api/send` با `sending_type: "webservice"`، `from_number`، `message` و `params.recipients`.
- ارسال قالب: `POST /api/send` با `sending_type: "pattern"`، کد Pattern، یک گیرنده و مقادیر `params`.
- دریافت قالب‌های فعال: `GET /api/patterns?page=1&per_page=100&filter[state]=active`.
- گزارش پیام: `GET /api/report/by_bulk?messages_outbox_id=...`.

درخواست‌های ارسال فقط از بک‌اند انجام می‌شوند. شناسهٔ خروجی IPPanel در گزارش سامانه نگه‌داری می‌شود. استعلام گزارش، کد وضعیت‌های IPPanel را مطابق مستندات رسمی نشان می‌دهد؛ `state_id=6` به معنی ارسال موفق پیام به اپراتور است و به‌تنهایی تأیید رسیدن به گوشی نیست.
