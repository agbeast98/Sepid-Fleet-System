# فرانت‌اند سامانه ناوگان سپید

پروژهٔ React و TypeScript از همین پوشه با `npm install` و سپس `npm run dev` اجرا می‌شود. Vite روی `http://127.0.0.1:55321` بالا می‌آید و درخواست‌های `/api` را به NestJS روی `http://127.0.0.1:55320` می‌فرستد. راه‌اندازی API و PostgreSQL در [راهنمای بک‌اند](../backend/README.md) آمده است؛ از ریشهٔ پروژه نیز `dev.bat` هر دو رابط را اجرا می‌کند.

فایل `legacy/index.html` نسخهٔ فعلی و قابل استفادهٔ آفلاین است. فایل‌های جاوااسکریپت، استایل، فونت و نسخهٔ تک‌فایلی آن در `legacy` قرار دارند تا برای انتقال صفحات و رفتارهای فعلی مرجع باشند. داده‌های IndexedDB مرورگر در این فایل‌ها ذخیره نشده‌اند. برای انتقال داده‌های ثبت‌شده، از همان نسخه و مرورگر قبلی خروجی پشتیبان بگیرید.

فرانت React ورود، کاربران و مجوزها، ماشین‌آلات و پرسنل، وضعیت ناوگان، تعمیرات و بایگانی، نگهداری و قطعات، تحلیل و اقدامات مدیریتی، گزارش‌ها، تنظیمات و پیامک را پوشش می‌دهد. دادهٔ عملیاتی از API خوانده و در PostgreSQL مشترک ذخیره می‌شود؛ IndexedDB مرورگر منبع دادهٔ React نیست. راه ساخت حساب مدیر در راهنمای بک‌اند آمده است.

در «قطعات و جایگزین‌ها» قطعه، دوره و جایگزین‌هایش را برای مدل ثبت کنید. سپس در «نگهداری پیشگیرانه»، ماشین را انتخاب و کارکرد یا سابقهٔ سرویس و تعویض را وارد کنید تا وضعیت موعد محاسبه شود. داشبورد آمار و روند ناوگان را نشان می‌دهد؛ گزارش‌ها و بایگانی نیز جست‌وجو، فیلتر، چاپ و CSV دارند.

مدیر کل می‌تواند «محیط سازگار با نسخهٔ قبلی» را باز کند. این محیط همان فایل‌های قدیمی را اجرا می‌کند، اما ذخیره‌سازی آن فضای سازگاری جداگانه روی سرور است و با جدول‌های عملیاتی React همگام‌سازی زنده ندارد. برای انتقال دادهٔ واقعیِ IndexedDB، از همان مرورگر قدیمی JSON بگیرید، پیش‌نمایش انتقال مدیر را بررسی کنید و سپس آن را به جدول‌های رابطه‌ای وارد کنید. پیش از انتقال نهایی، شمار رکوردها و روابط فایل واقعی را با مسئول داده تطبیق دهید.

برای ساخت، `npm run build` اجرا کنید. آزمون Chrome سرتاسری از پوشهٔ `backend` با `npm run test:browser` اجرا می‌شود؛ مسیر مرورگر را در `CHROME_BIN` بدهید. این آزمون از schema موقت استفاده می‌کند و دادهٔ توسعهٔ اصلی را تغییر نمی‌دهد.
